# Engineering delivery boundary

GitHub owns repositories, commits, contributors, PRs, checks and releases. Control Center stores bounded read-only observations with source links and observed/source timestamps. It never writes GitHub code or changes deployments. Project tasks and milestones are linked explicitly to persisted PR/release IDs, with composite foreign keys preventing cross-project associations.

A platform administrator approves a verified GitHub App installation/account for a particular project. A project manager discovers only repositories within that approved installation and explicitly connects one. Contributor/viewer project members read engineering observations; client roles receive no engineering data, even for shared projects. Unrelated/disabled/revoked identities deny. Product grants convey no engineering permission. Read RPCs recheck current project permission and hide observations/links when a connection or installation is disabled. Cached browser data is no-store.

Server-only installation tokens are short-lived, repository-scoped for synchronization and never persisted in the browser/database/logs. The approved App has metadata, contents, pull requests, actions and checks read permissions; no code/deployment writes. Operator-owned App installation approval is independent of project membership. No PAT collection UI is provided.

005 adds installation approvals, repository connections, observations, immutable event snapshots, explicit work links, webhook deduplication receipts and a service-only delivery_command. Sync claims use SKIP LOCKED and expiring fencing tokens. Each committed page is atomic with checkpoint and timeline updates. Disconnect invalidates in-flight leases. Provider failures persist bounded backoff; manual requests cannot shorten it. Installation revocation makes stored private observations unavailable. Data is retained for operator-governed recovery; disconnect does not delete audit/evidence. Up to 20 connections/project, 100 records/page, 10,000 records/connection and latest 200 visible records/events are supported; these are bounded recent-activity views, not a complete source-control archive.

No hosted installation is claimed. App credentials, installation/ownership approval and staging PostgREST/Auth verification are required. Vercel is disabled without an explicit verified project-to-provider mapping. See PHASE3_MIGRATIONS.md for the operational gate.
