# Project domain and authorization

Projects are internal work or customer engagements. Products linked through project_products are metadata, not entitlements. Customer ownership is immutable within this MVP; a customer project must name an organization, an internal project must not. Accountable owner is a mandatory active identity with a manager membership. Transfer ownership before removing that owner's access.

Explicit project roles: manager (manage project/team/work), contributor (read project, comment, update only assigned task status), viewer (read only), client (read only explicitly shared customer project and shared records, plus current active membership in that customer organization). Platform super_admin is the explicit portfolio administrator and can create/manage projects; product roles never authorize this module. Customer membership alone grants nothing. Disabled profiles, revoked project memberships and suspended customer memberships deny immediately on the next request. All mutations lock the project and recheck permission, use the caller's expected project version, increment version and write both activity and audit in one transaction. Conflicting edits return 409 rather than overwrite.

Tables: projects, project_memberships (with development-team label), project_products, project_milestones, project_tasks, project_comments, project_deliverables and project_activity. Same-project composite foreign keys prevent cross-project task/milestone/assignee/comment links. Owner/role/status, lifecycle and priority constraints apply in DB; structured API validation adds field allowlists and HTTPS link checks. No uploads are accepted. Client-facing comments/deliverables additionally require any linked task to be shared. Internal activity is private by default.

A project can move planned→active→paused/completed→archived, with controlled resume/restore. Completion requires all tasks/milestones resolved. Task transitions are explicit; done/cancelled reopening requires a manager. A milestone cannot finish with incomplete tasks/dependencies and cannot create dependency cycles. Archived projects are read-only except explicit platform restoration.

List reads are keyset paginated (50, UUID descending), with server search/state filters. This MVP caps projects at 500 tasks/100 milestones; detail returns those bounded work items and latest 200 comments/deliverables/events. Larger portfolios require further pagination. Project health is computed from actual visible tasks and milestone deadlines; no utilization/revenue/uptime numbers are invented. Development teams are per-project membership labels rather than a separate global organization hierarchy.
