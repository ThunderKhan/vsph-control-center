# Self-service portal sessions

007 adds random public UUIDs to portal sessions and a service-only session_command. Current authenticated users can list up to 100 of their unexpired portal sessions and revoke one other session or all their other sessions. The current session is preserved; ordinary logout handles that session. Revocation cascades linked product sessions and is audited in the same transaction. No token hashes, raw cookies, IP addresses or invented device names are returned. Creation/expiry timestamps are the only available session metadata.

Current hash comes exclusively from verified server middleware, never from request body. The RPC rechecks the active identity and unexpired current session. Profile-first locking serializes simultaneous revocations; a request whose session was just revoked fails closed. Wrong-user/public IDs do nothing; they never revoke someone else's access. Browser/anon roles cannot invoke the RPC directly. This does not add MFA, recovery, device fingerprinting or step-up authentication; those remain M3 work.

Projects → Your active sessions exposes inventory and individual/all-other revocation. Confirm before revoking. Native tests exercise hash privacy, ownership/current preservation, invalid credentials, product cascade and concurrent revoke requests. Desktop/mobile fixtures verify the browser remains authenticated after revoking other sessions. No hosted sessions or credentials were modified. Install and verify 007 in approved staging before enabling these routes/UI; no production deployment is authorized by this code merge.
