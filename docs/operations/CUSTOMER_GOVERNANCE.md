# Customer membership governance

The customer workspace at /admin/customers is platform-administrator-only, including fresh database-side actor checks. Existing organization/product administrators do not gain platform authority. Project permissions remain independent. Read models are bounded to 100 organizations, 200 members, 100 invitations/products/activity items and 500 product role assignments; these are explicitly MVP limits, not complete exports.

Migration 20261101052745_member_governance follows the checksummed prior migrations. It adds membership versions, a live-invitation uniqueness constraint and the customer_command transaction function, and extends provisioning_command. No hosted installation was performed. Preflight must check duplicate live organization/email invitations before creating the unique index; do not delete historical records automatically.

Individual invitations reuse existing stable Auth allocation, encrypted outbox delivery, purpose-bound capability and intended-membership-only acceptance. Inviting does not activate a membership. Select organization admin/member/viewer and each optional product role explicitly. App super_admin is a product role, never platform elevation. Product choices require a registered role and enabled organization grant; CRM cannot acquire Music-only staff/musician roles. Subscription effectiveness is still checked independently on access.

Idempotency-Key is a UUID bound to actor and exact invitation request. Matching retries return one job; changed payloads or a second live invitation conflict. Existing active memberships are edited through membership governance, not overwritten by invitations. Disabled identities and unprofiled Auth conflicts require review; workers must not reset existing passwords. Existing users sign in as the invited identity; new users enroll only through the existing reserved acceptance saga. Unknown external Auth effects still require reconciliation, not blind retry.

Cancellation invalidates the capability and encrypted delivery. Reissue uses the displayed generation as an optimistic precondition, rotates the generation, removes old proof/ciphertext/worker lease and queues new delivery. Expired sent invitations can be renewed. In-flight/ambiguous acceptance requires the existing reconciled recovery workflow first. Explicitly disabled enrollment cannot be renewed into activation. A delivery already in flight may still send an invalidated old URL; its capability cannot be accepted. No exactly-once external side-effect claim is made.

Membership/product-role changes lock and recheck actor/target/membership, use versions, record an audit in the transaction and revoke the affected customer product sessions/Music codes. The last active owner cannot be demoted/suspended by this workflow. Invited members must accept; administrators cannot shortcut acceptance with a status edit. Product role removal is explicit and cannot implicitly create an active membership. The legacy role endpoint now delegates to this transaction and requires an already active membership.

Use confirmation before membership suspension, product-role changes, cancellation and reissue. Reload after a conflict. The screen displays queued/sent/error/expiry state separately; it never assumes mail was delivered. Delivery remains off until an approved adapter and server-only credentials are configured. Existing password-provider and delivery-failure tests apply to the reused worker/acceptance implementation; native and browser fixtures do not certify live Auth/email.

Forward repair: pause the explicit invitation dispatcher and use reviewed state/version recovery; retain jobs, audit and invitation history. Do not run destructive down migrations or revert the backend to a role endpoint that creates active memberships implicitly. MFA/step-up, governed platform administrator recovery and organization-admin delegated invitations remain outstanding.

Phase 4 follow-up adds UUID-keyset organization directory pages and direct ID reads. Explicit account blocking is recorded separately from cancellation. Historical revoked invitations attached to disabled profiles are conservatively backfilled blocked; reviewed recovery is required rather than assuming those were ordinary cancellations. Cancellation, as well as reissue, requires the displayed generation. See CUSTOMER_LIFECYCLE.md for later suspension/terms and lock compatibility.
