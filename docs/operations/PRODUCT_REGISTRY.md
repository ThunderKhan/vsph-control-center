# Governed product registry

/admin/products is the platform-admin-only registration/edit/readiness workspace. Product metadata never grants tenant membership, a product role or project access. customer_command continues to enforce explicit per-organization grants/roles. Existing CRM/Music adapters and authorization remain authoritative.

Migration 20261101053314_product_registry follows member governance. Registration creates the product, standard product roles and one audit atomically. Client UUIDs give matching create retries a stable identity; changed payloads conflict. Updates require the displayed version; codes are immutable, login paths are derived from codes and retirement is terminal in this workflow. Disabled/maintenance/retired states block launches and revoke existing product sessions/codes in the transaction. Listed/unlisted controls catalog discovery, not direct-route authorization. Owners must refer to active profiles when assigned; legacy/unassigned ownership is displayed honestly.

Allowed metadata: name, description, owner account, support email, HTTPS documentation URL, lifecycle, visibility and reviewed integration mode. The API/database reject unknown fields. No token, key, client secret, database name, operational table, executable module or arbitrary provider URL is accepted from a registry form. Safe integration choices are reviewed adapter or portal-only fallback; built-in CRM/Music adapters cannot be replaced by metadata edits. Music SSO settings remain server-owned and separately gated. The public demo never proves integration ownership/security.

Readiness distinguishes configured, reachable (reviewed local database adapter only), degraded and unavailable. End-to-end verified is always false until separate staged provider/Auth acceptance exists; no manual green verification toggle exists. An explicit check queries only the adapter's fixed allowlisted table, never an admin-supplied URL. It stores timestamp/scope/result in an RLS-protected, service-only observation with a version fence. A successful local Music table query is not an external reachability or SSO assertion. Historical observations have timestamps and may be stale after edits; current lifecycle/configuration is shown separately.

Legacy nontransactional product write endpoints return 410 pointing to the registry. The administration catalog links directly to the governed editor, and its former add form is hidden. No schema or seed rerun is used for registry operations. The manifest and fresh/populated/native restore/browser checks include the new migration; all hosted installation and real provider verification remain gated.

Recovery: disable access through a reviewed lifecycle change, preserve audit/observation history and forward repair. Do not delete products with customer/project references. No automatic deployment, provider configuration, secret rotation or customer-data removal occurs. Health probes cannot mark external acceptance verified. Full secret-service integration and provider acceptance remain operational requirements.
