# Authorized project summary export

Projects → Project inbox and reports → Filter report → Download project summary CSV exports the currently applied authorized report selection. Changing a form value does not change the export until Filter report succeeds. Filters cover exact project/customer/owner, project status and project creation dates. The HTTP endpoint is `GET /api/project-reports/export.csv` with the same validated query fields as the JSON endpoint.

The database report remains the authorization source. Manager/contributor/viewer project permissions are required; client-only, revoked and unrelated memberships cannot expose internal engineering reports. Platform project administration follows the existing project permission model. A portal session must be current and the identity active on every request. The CSV endpoint grants no new project or product privileges.

The file contains at most the first 100 matching authorized projects, exactly as the existing report does. This limit appears in the link, response scope header and each populated row. Empty results contain column headers only. Explicit columns cover project identity, owner/customer, due date, task/milestone counts, requested PR reviews, retained failed build observations, last repository sync/activity and the report generation time. Deployment status remains honestly unconfigured; build observations are not uptime, productivity scores or forecasts. No raw GitHub records, tokens, email directory, audit payloads or arbitrary object columns are exported.

UTF-8 BOM, CRLF records and quoted cells support common Windows spreadsheet readers. Quotes inside cells are escaped, and formula-significant text prefixes (including whitespace before `=`, `+`, `-` or `@`) are neutralized with an apostrophe. Null bytes are removed. These protections supplement authorization; downloaded information still requires appropriate handling. Files are served with a fixed attachment name and no-store headers. Permission revocation stops future downloads, not copies already saved outside the application.

No new database migration, provider, background worker or hosting action is required. This endpoint uses the existing `project_report` function. Rollback is the route, utility, link and associated tests; no stored data is changed. Broader pagination/export scopes, global search, export-event auditing and retention policies remain follow-up work.

Acceptance covers formula/quote/control characters, explicit column allowlists, maximum size, strict filters, anonymous/expired sessions, client-only reports, revoked project membership and permitted engineering access against native PostgreSQL. Desktop/mobile Chromium download the filtered fixture report and inspect its contents. These fixtures do not certify a live hosted session or external provider.
